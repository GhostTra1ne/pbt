# Pussy Boys Team / UaSquad

Сайт КП Lineage 2, размещённый на GitHub Pages. Домен из `CNAME`: https://pussyboys.team.

## Изменения

- Новая отдельная страница `death-note.html`: общая тетрадь, поиск, форма заявки, закрытая очередь модерации.
- Публикация только после одобрения. Отклонение не публикует запись. Автор и доказательства доступны только хранителю.
- Обработчик Cloudflare Worker + D1 хранит общие данные независимо от браузера. Ключ хранителя передаётся по HTTPS и хранится в памяти вкладки до закрытия админки; в клиентских файлах секретов нет.
- Три заявки в час с одного IP, honeypot, ограничение размера, проверка полей и схемы URL. Это базовая защита; при публичном спаме стоит добавить Turnstile.
- WebP вместо крупных PNG: 35 590 696 → 3 556 476 байт для конвертированных изображений. Исходники сохранены. Ленивая загрузка нижних блоков, ограничение плотности canvas и количества частиц, поддержка reduced motion.
- Существующая форма вступления в КП и данные состава сохранены.

## Локальный просмотр с работающей модерацией

Нужен Node.js 24 с `node:sqlite`. Зависимости устанавливать не требуется.

```powershell
node backend/preview.mjs
```

Открыть http://127.0.0.1:8788/death-note.html. Ключ **только локального демонстрационного режима**: `preview-only-key-do-not-use-in-production`.

В этом режиме база находится в памяти и очищается после остановки. Уведомления наружу не отправляются. Файл `death-note-config.js` сервер подменяет только в локальном просмотре.

```powershell
node --test backend/worker.test.mjs
```

Тесты проверяют приватность до одобрения, авторизацию, одобрение/отклонение, повторное решение, исключение приватных полей, лимиты, CORS и валидацию.

## Подключение общего архива

GitHub Pages выполняет только клиентский код. Для настоящих заявок нужно один раз опубликовать Worker в собственном аккаунте Cloudflare и создать D1.

1. В каталоге `backend` выполнить `npx wrangler login`, затем `npx wrangler d1 create pbt-death-note`.
2. Подставить возвращённый `database_id` в `backend/wrangler.toml` вместо `REPLACE_WITH_CREATED_D1_ID`.
3. Выполнить `npx wrangler d1 execute pbt-death-note --remote --file=schema.sql`.
4. Создать длинный случайный ключ (минимум 24 символа) и сохранить через `npx wrangler secret put ADMIN_KEY`. Не записывать ключ в репозиторий или `death-note-config.js`.
5. Выполнить `npx wrangler secret put RATE_SALT`, указав другое случайное значение для хеширования IP.
6. Выполнить `npx wrangler deploy`.
7. Записать возвращённый HTTPS URL Worker в `window.DEATH_NOTE_API` в `death-note-config.js`, затем опубликовать клиентские файлы через существующий GitHub Pages.
8. Проверить на домене: отправка заявки → отсутствие в общем списке → вход хранителя → одобрение → появление у другого посетителя. Отдельно проверить отклонение.

`ALLOWED_ORIGINS` в `wrangler.toml` содержит текущий домен, GitHub Pages и локальные адреса. После проверки локальные origin можно удалить. Домен менять не требуется.

### Уведомления в Telegram (необязательно)

Сохранить через `wrangler secret put` значения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, затем повторно развернуть Worker. Бот отправляет уведомление со ссылкой на страницу; одобрение выполняется в защищённой админке сайта. Токен бота никогда не передаётся клиенту.

Без URL API страница честно показывает, что приём заявок ещё не подключён, и не имитирует успешную отправку.
